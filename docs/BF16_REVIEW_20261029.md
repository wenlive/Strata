## Scope and correctness

All 10,240 routed experts are retained in BF16: 60 GiB, 6 MiB per expert.
Clover text weights total 69,322,701,696 bytes; Qwen text 69,321,221,376 bytes.
Clover uses all 28 official weight files, including additional GDN parameters.
Qwen vision/MTP tensors are classified and retained, not run by the text adapter.
Direct safetensors slicing avoids another full pack. RAM, VRAM and staging
budgets are independent; no full host expert bank or forced GPU/RAM duplicate.

Both native builds passed. Fresh tests passed: 24 synthetic expert/cache cases
per branch, 12 real Clover expert cases, 154 kernel comparisons, 190 real Clover
layer comparisons, 50 denoise controller cases and 126 exact decision cases.
Clover causal/preview routing tests each cover 40 real layers plus eight synthetic
cases; same-input CUDA weights are bit equal. Real preview coreset/ID choices
also agree. Qwen same-input 40-layer routing weights are bit equal.

Native causal state replay passed for both models. Clover selfspec, denoise tail,
forced fallback and full32 commit replay each passed all 80 state files by byte
comparison. Controlled verify cases accept 7, 3 and 0 draft tokens; all 240 layer
state files and three metadata files match causal replay hashes. Qwen's 80 state
files also match hashes. These validate native state handling, not HF parity.

The Qwen complete-model RMS increased from the historical 0.032094. Its selected
layer-3 tensor comparisons pass, but one routing-weight comparison remains failed
at RMS 0.004426, maximum two BF16 ULPs, with equal expert sets. Do not call the
new arithmetic an overall numerical parity fix. It fixes specific operation
boundaries while preserving unresolved integration differences.

Identical-input and diagnostic controls distinguish slot order from expert sets,
rounding from storage, and local error from routed amplification. HF versus HF
with only padded GEMM row geometry changed already has RMS 0.090823 and three
prefill argmax differences. Replacing HF router logits with native saved values
is diagnostic only. Some intermediate-position probability differences remain
large (current Clover maximum KL about 4.265, TV about 0.939); matching the last
argmax is insufficient. Preview conditions on identical native committed history
and does not establish independent full HF generation equivalence.

counters add that context. Physical SSD bytes and proven cold-I/O are unmeasured.

## Reproduction and report

Use the branch's Windows build/download/index/run guide. The Clover branch has
`tools/clover/benchmark_denoising.py --help` for identical request controls and
`tools/clover/write_bf16_review_html.py --data JSON --output REPORT.html` for
the offline, self-contained report. Its measured input schema is the JSON above.
The desktop report includes interactive prompt/repeat/metric controls, raw output
examples, per-layer numerical errors, memory and phase breakdowns, sources and
local raw evidence links. It has no CDN or external script dependency.

NVFP4 is excluded as requested. Generic kernel support does not establish the
specific Qwen3.6 HF mixed-FP8/NVFP4 loader and projection-scale path. No other
framework is used to manufacture a comparison row.
